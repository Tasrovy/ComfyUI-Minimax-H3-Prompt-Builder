# MiniMax H3 REF 时间轴提示词构建器

这是一个 ComfyUI 自定义节点包，用人物卡、人物实例、环境卡、时间轴片段和统一轨道数组构建 MiniMax H3 Ref2VA 提示词，并支持自动多段生成、段间连续性和分段缓存。

## 数据流

```text
人物卡 -> 人物实例 -> 人物组
                    \-> 人物轨道 --\
环境卡 -> 环境实例 -> 环境轨道 --------\
摄像机 / 灯光 / 音频片段 -> 系统轨道 ----> 轨道数组
风格卡 + 人物组 + 环境实例 + 轨道数组 -> 时间轴
时间轴 -> 最终提示词 -> 提示词解析 -> Ref2VA 适配器
时间轴 -> 生成任务包 -> 多段生成 -> VIDEO
                      \-> 最终提示词预览
Ref2VA 适配器 -> 第一次采样 LATENT -> 二次采样放大 -> VIDEO
```

所有集合节点都使用 ComfyUI 原生自动增长插槽。连接最后一个插槽后，会自动出现下一个插槽。

## 卡片与实例

- 人物卡只保存人物名称、固定外观、身份参考图和可选的人物专属风格。不要在人物外观中写动作、姿势、表情、位置、场景或镜头。
- 人物实例只保存没有动作指引时使用的位置、姿势、表情和附加静态状态。当前生成片段中只要该人物存在动作片段，人物实例状态就完全不进入提示词。
- 人物组按照插槽连接顺序声明人物实例，并自动分配 `S1`、`S2` 等编号。
- 环境卡只保存空间结构、建筑、固定背景、陈设和材质；环境实例保存当前时间、天气、氛围及当前实例的静态变体。环境变化过程只写在环境动作片段中。
- 风格卡提供全局视觉风格。人物卡可以设置人物专属风格与全局风格冲突时的优先级。

人物实例中的备用状态应写成静态谓语，例如写 `站在路灯下`，而不是 `走向路灯` 或 `L 站在路灯下`。编译器会自动补上当前人物名称；动作、对话、视线和表情变化必须由动作片段描述。

提示词编译遵循单一职责和最小输出原则：人物卡不提供行为，环境卡不提供变化，人物实例不与动作片段同时输出。同一事实只由一个模块负责，避免卡片、实例和时间轴生成相互冲突的指令。

旧工作流加载时会自动移除人物卡里的默认位置、姿态、表情、默认外观，以及环境卡里的时间、天气和氛围字段，防止旧内容错位到新卡片。仍需作为无动作备用状态使用的内容，应重新填写到对应的人物实例或环境实例中。

人物卡是保存真实人物名称的唯一权威来源。每个人物实例必须声明唯一宏名，例如 `actor_1`、`actor_2`；动作、对白、镜头、灯光、音频、环境、风格和附加指令等其他提示词字段推荐只通过 `{actor_1}`、`{actor_2}` 引用人物。直接写人物名称仍可编译，但不利于重命名、多人物映射和项目复用。编译器会在最终输出前把宏替换为人物卡名称；宏未声明、格式错误或重复时会停止编译。旧工作流和旧项目文件会按人物组顺序自动迁移宏。

## 时间轴

人物动作片段可以选择以下种类：

- `body`：身体动作
- `expression`：表情
- `gaze`：视线
- `speech`：说话

语言是 `speech` 动作的输入。摄像机、灯光、音频和环境节点也会输出统一的 `MINIMAX_H3_TIMELINE_CLIP` 类型。

所有轨道统一输出 `MINIMAX_H3_TIMELINE_TRACK`，因此轨道数组接收统一的轨道列表，不需要分别设置人物、摄像机、灯光、音频和环境输入。

时间单位为秒，并按照左闭右开区间 `[开始, 结束)` 判断。动作过程在结束时间停止；非空的“结束状态”会持续到同一种类的下一个动作开始。音频只在自身时间范围内生效，并且允许不同音频相互重叠。

以下情况会停止编译并报告错误：

- 同一对象、同一种类的非音频片段发生重叠。
- 片段超出时间轴总时长。
- 轨道引用了人物组中未声明的人物。
- 环境轨道引用了时间轴之外的其他环境实例。

## 导演时间轴编辑器

节点包内置独立的可视化编辑界面。它采用与 BSK UI 类似的“从工作流提取参数、在独立面板编辑、再同步回原节点”方式。当前工作流中的节点仍是提示词编译的唯一数据源；独立 JSON 只作为可复用卡片模板库，不参与运行时编译。

可以从顶部菜单 **MiniMax H3 → 导演时间轴编辑器** 打开，也可以点击 **MiniMax H3 总时间轴** 节点上的“打开导演时间轴”按钮。界面包含：

- 左侧场景资源栏：查看并编辑当前时间轴连接的人物实例、人物卡、环境实例、环境卡和全局风格；“卡片”页可以自主创建卡片，“参考视频”页管理预处理媒体资产。
- 中央多轨时间轴：按人物、环境、镜头、灯光和音频显示片段；拖动片段改变起止时间，拖动两端改变片段长度。
- 时间尺与播放指针：支持缩放、时间吸附、适应宽度和静态预演时间顺序。播放指针只预演调度，不执行视频生成。
- 右侧属性栏：编辑当前片段或场景资源的原始节点参数，并可定位回节点图。
- 冲突提示：同一轨道、同一种类的非音频片段发生重叠时，片段会显示红色边框。

点击顶部“＋轨道”可以直接创建人物肢体、人物表情、人物视线、环境、镜头、灯光或音频轨道，并同时创建第一个片段。每条轨道左侧的“＋”用于继续添加片段。前端创建的内容都是实际 ComfyUI 节点和连线，不是仅供界面显示的副本；人物轨道只能选择当前人物组成员，环境轨道只使用当前环境实例，系统轨道会按片段语义自动建立。

工作流中只有一个总时间轴节点时，点击“补全工程”会创建并连接最小可编辑工程：人物卡、人物实例、人物组、环境卡、环境实例、风格卡、轨道数组和首条人物轨道。编辑器会始终按参考媒体、卡片、实例、片段、轨道和总时间轴的列顺序自动排布，创建卡片、轨道、参考媒体或导入项目后无需手动整理。

顶部“自动保存”默认开启。对节点参数、片段时间、连线或节点结构的修改会在停止操作约 1.8 秒后调用 ComfyUI 原生工作流保存命令；未命名工作流会等待用户先点击一次“保存”并选择名称。也可以关闭自动保存，只使用旁边的手动“保存”按钮。

顶部“导出 JSON”会把当前总时间轴保存为可读的 `.h3proj.json`。该文件只保存人物、环境、风格、轨道、片段、语言、媒体相对路径和生成语义，不保存 ComfyUI 节点 ID、坐标、连线编号或编译后的最终提示词，因此适合版本管理和交给 AI 修改。媒体路径必须指向 ComfyUI `input` 目录内的相对路径；JSON 本身不内嵌图片或视频。

“打包项目”会生成可携带的 `.h3proj` ZIP 包，包含 `project.json` 和当前工程实际引用的图片、参考视频及缓存视频。“导入并覆盖”同时支持 `.h3proj.json` 和 `.h3proj`；导入包时会把媒体恢复到 `ComfyUI/input/minimax_h3/projects/<项目 ID>/`。导入会复用当前选中的总时间轴节点，替换它的卡片、实例、片段和轨道，同时保留该总时间轴的全部下游提示词、生成、采样、解码和保存连线。新工程构建失败时会恢复原有输入连接。格式定义见 `project_format.schema.json`，最小示例见 `project_format.example.json`。

“清理未使用节点”以当前选中的总时间轴为工程根节点，同时沿输入和输出连线保留整个连接链。清理范围只包括本节点包的工程节点，以及前端创建或位于 `minimax_h3/` 资源目录下的图片、视频加载节点；模型、CLIP、VAE、LoRA、采样、解码、保存和其他第三方节点即使未连接也不会被该功能删除。

选择人物、镜头、灯光或音频片段后，右侧属性栏会显示对应的参考视频区域。人物动作参考会在“参考视频语义拆分”之后增加“参考视频人物解释”，用 `person_1`、`person_2` 和可见特征说明当前轨道跟随源视频中的哪位人物；镜头、灯光和音频仍直接使用各自类型化输出。由原生加载视频节点提供的参考视频可以在属性栏直接播放预览并编辑人物解释。参考视频实际截取范围仍由语义拆分节点的开始和结束时间控制，单个输入继续遵守 H3 最长 15 秒限制。

需要重复使用的参考视频应在左侧“参考视频”页预先导入。导入器按指定区间截取，使用本机 FFmpeg 转为 24 FPS MP4，保留原宽高比并生成独立资产 JSON。点击资产“属性”可编辑视频内容说明，并添加最多 32 个源人物声明。选中人物动作片段后，资产卡会按人物声明显示连接按钮；选择其中一人时自动创建“加载视频＋语义拆分＋人物解释”并连接当前人物轨道。资产元数据保存在 `ComfyUI/user/minimax_h3/reference_videos/<id>.json`，媒体保存在 `ComfyUI/input/minimax_h3/reference_videos/<id>.mp4`。从资产库移除只删除元数据，已有节点和媒体文件保持可用。

资源库采用“索引＋独立卡片文件”结构，保存在：

```text
ComfyUI/user/minimax_h3/resources/library.json                 # 资源库索引与版本
ComfyUI/user/minimax_h3/resources/cards/character/<id>.json   # 单个人物卡
ComfyUI/user/minimax_h3/resources/cards/environment/<id>.json # 单个环境卡
ComfyUI/user/minimax_h3/resources/cards/style/<id>.json       # 单个风格卡
```

`library.json` 只保存 `minimax-h3-resource-index` 索引元数据，不再把所有卡片塞进一个文件。每张卡都是 `minimax-h3-resource-card` 文档，包含稳定的 `kind`、`id`、自身版本、显示名称、标签、可选参考图和 `data`。把一个卡片 JSON 放入对应目录后即可被资源库发现，便于单独分享、版本管理和由其他节点包生成。

卡片和索引都预留 `extensions` 对象。第三方节点包应使用自己的反向域名或仓库名作为键，例如 `"com.example.motion": {...}`，不要修改核心 `data` 字段的语义。非核心 `kind` 也会作为扩展卡片保留，当前编辑器不会擅自解释或实例化它。旧版 `minimax-h3-resource-library` 单文件仍可读取，下一次保存时会自动拆分成独立卡片文件。

参考图只保存经过校验的 ComfyUI `input` 相对路径，不把图片二进制写进 JSON，也不接受绝对路径。

点击“＋人物”“＋环境”或“＋风格”可以直接填写文字字段、标签、实例默认状态和可选参考图。保存只创建资源卡片，不改变工作流。点击资源上的“实例化”后才会创建节点：人物生成“人物卡＋人物实例＋人物轨道”，环境生成“环境卡＋环境实例＋环境轨道”，风格生成风格卡；存在当前总时间轴时，会自动连接人物组、环境输入、风格输入和轨道数组的空闲自动增长插槽。参考图会通过原生 `LoadImage` 节点连接。

选中人物实例后，可以点击右侧的“保存为人物卡”。编辑器会把人物卡中的固定外观与风格、人物实例中的默认位置/姿态/表情/附加状态以及可识别的原生加载图片引用复制到一个新的独立人物卡资源中。保存采用快照，不修改原人物实例，也不把动作轨道内容写入人物卡。

选中人物后，右侧“人物卡”区域可以从“选择已有人物卡”下拉框直接应用资源库中的人物卡。该操作只替换人物卡的名称、固定外观、人物风格、风格优先级和参考图；当前人物实例的位置、姿态、表情、附加状态以及已经连接的动作轨道都保持不变。

资源实例采用快照原则。节点的 `properties.minimax_h3_resource` 会记录资源库、资源 ID 和版本，但之后修改或删除 JSON 资源不会偷偷改变已经实例化的工作流节点。动作、对话、镜头、灯光和环境变化仍由时间轴片段管理，不进入卡片资源库。

## 多段生成

模型加载器和模型补丁节点继续使用 ComfyUI 原生节点。将处理后的 `MODEL`、`CLIP`、视频 `VAE`、音频 `VAE` 和 `SAMPLER` 直接连接到 **MiniMax H3 多段生成（Decoded Video）**。提示词、参考素材、尺寸、种子、采样和分段参数由 **MiniMax H3 生成任务包（Generation Job）** 一次性打包。

生成片段由时间轴动作自动划分，而不是按固定时长切割：

- 不重叠的人物动作形成前后相继的生成片段。
- 时间重叠的人物动作在同一个片段中一起生成。
- 没有人物动作时，由环境变化片段提供分段结构。
- 摄像机、灯光和音频是辅助控制轨道，只会被裁入其覆盖的片段，不会单独创建分段边界。

多段生成节点会保留每个内部步骤的耗时记录，并实时显示当前步骤、采样步数、总体百分比和累计耗时。内部展开图的进度会映射回可见的多段生成节点，不需要把紧凑工作流手动拆成多条采样链。

采样期间不生成额外预览。每个片段完成 VAE 解码后，会立即把包含强锁定上下文和 H3 合法时间长度的未裁剪音视频保存到：

```text
ComfyUI/output/video/MiniMax H3 Segments
```

保存完成的未裁剪片段会显示在多段生成节点的视频列表中，同时保存对应的视频＋音频 Latent 侧车文件。保存成功后，节点才从该文件读取音视频、移除重复的强锁定区，并把其后的连续生成部分用于最终时间轴拼接。点击“停止生成并保留已完成片段”或使用 ComfyUI 的停止功能后，已经完成的原始片段和 Latent 不会丢失，当前尚未完成的片段不会保存。

通过“动作片段结果扩展”直接提供的视频没有模型生成上下文，因此仍按对应时间轴片段的可见长度保存。

设置 `分段缓存 = 复用已完成片段` 后，再次执行会读取内容匹配的片段及其 Latent，从第一个缺失或变化的片段继续。缓存标识包含提示词、时间范围、参考素材、生成设置、模型结构和上游片段。旧缓存只有 MP4、直接结果没有 Latent 时，会自动回退到尾部画面和音频重新编码。更换模型、CLIP、VAE 或采样器实现后，需要增加“缓存版本”。选择“重新生成全部片段”可以在本次执行中忽略已有缓存。

## 直接使用已经生成的片段

使用 **MiniMax H3 动作片段结果扩展（Use Result）** 可以让某个生成片段直接采用已有视频，不再执行模型采样：

```text
人物动作片段 -> 动作片段结果扩展 -> 人物轨道
加载视频 -----------------------> 已生成结果
```

该结果会覆盖动作所在的整个生成片段。首次使用时，节点会将它统一为当前任务的分辨率、24 FPS、片段时长和双声道音频，然后保存到分段缓存。以后缓存命中时会直接读取视频。

直接结果也是一个连续性重置点，因此它之前的内容发生变化时，不会使这个固定结果及其后续片段失效；它后面的片段会使用该结果的尾部作为段间引导。替换输入视频后，需要增加扩展节点上的“结果版本”，从而使当前结果和依赖它的后续缓存失效。

人物动作片段可选择完整段间引导、仅段间音频引导或关闭引导。启用“仅段间音频引导”会覆盖完整引导开关：保留动态前缀和裁切规则，只强锁定上一片段末尾音频，画面不继承上一段，适合切换场景但仍需保持对白、环境声或音乐连续的片段。

同一个生成片段只能绑定一个直接结果。输入视频不能短于对应片段；较长视频会按照片段时长截取。

## 段间连续性

每个生成片段都使用 Ref2VA。后续片段优先直接截取上一轮采样结果末尾的视频＋音频 Latent，写入新片段的潜变量前缀，并使用零降噪遮罩将这部分内容硬锁定，避免解码后再次编码造成漂移。只有上一段没有 Latent 时才从尾部画面和音频重新编码。连续性不依赖模型理解 `<Video 1>` 之类的文字说明。

模型会依次处理“强锁定的上一段尾部、当前可见动作”。节点从 H3 可完整表示的 Latent 窗口中动态选择实际锁定长度，再把模型合法总帧数减去锁定帧数作为本段实际输出长度。因此实际片段可能略长于时间轴填写值，但不会在锁定区和当前动作之间插入随后又被裁掉的过渡帧。动作和镜头参考会重定时到动态输出长度，其起点对应裁切后第 0 帧，终点对应模型生成最后一帧。解码后只移除重复的强锁定区并直接拼接，不进行段后补齐或交叉淡化。段间连续性前缀不会占用 Ref2VA 的语义参考视频插槽。

音频裁切直接依附最终保留的画面帧数：先按相同的前置帧时长裁掉音频开头，再将每段音频严格限制为“保留帧数 ÷ 24 FPS”。解码音频过长时截断，不足时在末尾补静音；拼接时允许并自动修正最多 8 个采样点的正常取整差，再按累计画面帧数统一音频总长度。只有超过该范围的真实音画不一致才会停止执行。

展开后的生成图继续复用 ComfyUI 原生的引导器、调度器、采样器、VAE 解码器和视频容器。节点最终输出包含画面和音频的原生 `VIDEO`。

## 二次采样放大

**MiniMax H3 二次采样放大（Second Pass Upscale）** 封装了放大后二次采样链路。连接方式如下：

```text
Ref2VA 适配器 positive -----------> conditioning
第一次采样器 output --------------> first_pass_latent
MODEL / 视频 VAE / 音频 VAE / SAMPLER -> 二次采样放大 -> VIDEO
```

节点会分离第一次采样的画面与音频潜变量，解码画面并按“二采百万像素”和“二采宽高比”放大，再用视频 VAE 重新编码。音频直接沿用第一次采样的音频潜变量，之后复用原条件执行低降噪二采并解码为带声音的原生 `VIDEO`。

节点面板可以直接调整二采百万像素、宽高比、画面放大算法、拉伸或居中裁切、采样器、噪声种子、调度器、采样步数和降噪强度。默认使用 `Lanczos / euler / beta / 4 步 / 0.2`。`SAMPLER` 插口是可选覆盖：不连接时使用面板中的采样器，连接后使用外部采样器。

单段工作流仍可使用上述节点。多段工作流将 **MiniMax H3 多段生成（Decoded Video）** 新增的 `second_pass_batch` 输出连接到 **MiniMax H3 多段二次采样（Decoded Video）**。任务包会按片段携带原条件、未裁剪一采视频、音视频 Latent、锁定帧数和缓存标识；二采节点逐段放大、重新编码、低降噪采样，并用上一段二采 Latent 强锁定下一段开头。

多段二采与一采使用相同的执行体验：每完成一段就保存未裁剪 MP4 和对应 Latent，节点内累计显示已完成片段预览、当前步骤与耗时；中断后再次运行可复用已经完成的二采缓存。`second_pass_batch` 的每个片段同时保存原时间轴起止时间、上下文帧数、模型输入总帧数和最终可见帧数，二采裁剪与拼接只使用任务包中的划分，不重新读取或推测时间轴。时间轴中直接接入的已有结果只做尺寸处理并参与最终拼接，不会被模型重新生成。

安装 `Comfyui_Minimax_h3_latent_Upscaler` 后，也可以把任务包连接到 **MiniMax H3 多段 Latent 模型二采（Decoded Video）**。该节点直接用 `MinimaxH3LatentUpscaler3D` 放大每段画面 Latent，保留原音频 Latent，再执行低降噪二采；放大后的段间锁定、未裁剪缓存、按帧裁切和最终音视频拼接均在节点内自动完成。可选的 `SIGMAS` 输入用于复用手工二采计划，未连接时使用节点内的调度器、步数和降噪强度。

需要改接其他升分辨率或重采样流程时，将 `second_pass_batch` 连接到 **MiniMax H3 二采任务解析（Second Pass Batch Parser）**。节点按片段输出一采 `LATENT`、`CONDITIONING`、未裁剪 `VIDEO`、片段编号、锁定帧数、生成帧数、可见时长和缓存文件名列表；下游节点会按相同顺序逐项执行。直接导入的已有结果没有可复用的 Latent 和 Conditioning，因此不会进入这些采样列表。

## 参考视频语义拆分

**MiniMax H3 参考视频语义拆分（Reference Split）** 对一份原生 `VIDEO` 完成一次截取，并输出四种类型化引用：

- 人物表演参考：连接人物动作片段。
- 镜头参考：连接摄像机片段。
- 灯光参考：连接灯光片段。
- 音频参考：连接音频片段；源视频没有音频时会停止执行。

**MiniMax H3 参考视频人物解释（Video Person）** 包装一路“人物表演参考”，声明源人物编号和稳定可见的识别特征。双人参考视频可以从同一个拆分节点拉出两路人物表演，分别经过 `person_1` 和 `person_2` 的解释节点，再连接两个目标人物轨道。编译器会把两位源人物分别声明为动作 `<Subject N>`，只迁移指定人物的动作顺序、重心和最终姿态，避免混用同画面其他表演者的动作。项目导入导出会保留人物编号与识别描述。

这只是语义职责拆分，不执行姿态、相机参数或光照的像素级分离。四个输出共享同一份源视频数据，不复制视频张量。用户只连接需要的语义；未连接的语义不会进入提示词。

旧工作流中的参考视频节点会自动移除“参考范围”和“包含参考音频”控件，并保留原有第一个输出到人物动作片段的连接。原来依靠“动作与镜头”“完整表演”或“包含参考音频”的工作流，需要把新的镜头、灯光或音频输出显式连接到对应片段。

最终编译器按照源视频、截取范围和轨道时间合并引用。同一源视频在同一时间范围内同时承担人物表演、镜头、灯光和音频职责时，只占用一个 `<Video N>` 媒体槽位，音轨作为该视频对应的 `<Audio N>` 输入；不同时间范围会保留为不同媒体。每个生成片段最多支持三个参考视频和三个参考音频，硬锁定的段间连续性前缀不占媒体槽位。

提示词严格按 Ref2VA 语义生成：人物表演和灯光是可转移的 `<Subject N>`，使用 `attribute_transfer`；只有镜头运动、时间结构或段间延续关系使用独立的 `<Video N>` 定义；音频独立编号为 `<Audio N>` 并使用 `reference`。同一标签在 `subject_definitions`、`summary`、`retention_analysis` 和 `detailed_description` 中保持同一含义。

连接镜头参考或灯光参考后，对应片段里的文字镜头/灯光描述不会编译，参考媒体成为该轨道的唯一权威来源。人物动作文字仍可说明目标行为，但具体动作顺序、节奏、重心变化和结束姿势由人物表演参考负责。只要人物存在任何动作片段，人物实例中的备用状态就不会写入该片段。

动作片段会自动把完整参考动作重定时到当前动态输出长度。后续片段的动作参考前会加入与潜空间锁定长度相同的上下文：运行时优先采用上一段实际生成画面的尾部，使语义参考和真实拼接边界一致；仅在提示词预览等尚未生成上一段画面的阶段使用上一片段同人物动作参考的尾部作为占位。这样动作参考、潜空间前缀和本次模型输入逐帧对齐，不再依赖模型理解文字时间偏移。

当前引用按照24 FPS重定时到本段动态输出长度。后续片段通过动态 Latent 锁定窗口对齐 MiniMax H3 的 `17k+5` 帧数规则，第一片段则直接使用向上对齐后的合法长度。动作末尾不重复最终姿势，也不丢弃锁定尾帧与当前动作之间的生成帧。只有音频参考输出实际连接到音频片段时才会创建 `<Audio n>`；源视频包含声音但未连接音频语义，不会自动引用声音。

每次模型采样以生成目标帧数作为唯一时间基准。送入该次采样的每个动作参考 `<Video n>`、对应参考音频和模型解码结果必须与目标严格等长；编译器和裁切节点都会检查长度，任何不一致都会停止执行并报告具体帧数。最终时间轴视频是在等长采样完成后只移除重复锁定区得到的，不改变模型输入阶段的逐帧对应关系。

生成任务包中的“参考媒体尺寸”同时控制参考图片和语义参考视频：

- `match`：按照生成片段的像素面积缩小参考素材，同时保持原始宽高比。
- `max`：保留参考素材的原始高质量画布。

显存有限时建议使用 `match`，因为每个参考视频的 Token 都会参与每一步采样。

## 最终提示词预览

把同一个生成任务包连接到 **MiniMax H3 最终提示词预览（Final Prompt Preview）**，可以检查每个实际生成片段的完整 Ref2VA 提示词。预览内容包括：

- 原时间轴范围和输出时长。
- 硬锁定段间上下文的长度。
- 语义参考视频及其职责。
- 是否使用已有结果并跳过模型采样。

## 输出与尺寸

独立提示词编译器会生成包含六个固定部分的连续单镜头 `Ref` 提示词。`<Subject n>` 与 `<Picture n>` 分别编号，因此同一张参考图可以安全定义多个人物、环境或风格。提示词解析节点按照 `<Picture n>` 的顺序输出参考图片。多段生成的每个片段统一编译为 `Ref`，后续片段不会切换成 FL/I2VA。

独立编译器的 `FL` 入口会根据关键帧输入自动选择官方基础模式：无图为 T2VA、仅首帧为 I2VA、仅尾帧为 L2VA、首尾帧同时存在为 FL2VA，并在提示词首行写入对应的图片时间对齐说明。

编译器采用最小充分约束：摘要突出当前片段的主要动作，参考图片分别只承担人物身份、环境或视觉风格职责；时间顺序、合法帧补齐、段间连续性和缓存等工程规则由节点执行，不再重复写成长串禁止指令。持续音频只进入对应的声音段落，避免与画面描述重复。

分段提示词以本次送入模型的原始生成长度为时间基准。后续片段先描述强锁定区，再从紧邻锁定尾帧的局部时间点描述当前动作；第一段直接按动态合法长度描述完整动作。当前动作始终持续到模型生成的最后一帧，裁掉锁定区后的动态成片时长会显示在最终提示词预览中。

宽度和高度按照百万像素与宽高比计算，并取最接近的 32 倍数。时长按照 24 FPS 转换为帧数，再向上对齐到 MiniMax H3 使用的 `17k+5` 帧数规则。
